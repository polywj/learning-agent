# Ingest

1. Find new source files in `materials/` (any depth; note the subfolder). Do not treat generated files under `materials/md/` as source materials.
2. The command examples below use Windows PowerShell and `.venv\Scripts\python.exe`. On other platforms, invoke the same scripts with the virtual environment's Python executable and the platform's shell syntax. PDF conversion does not require PowerPoint. PPTX and legacy PPT conversion require Windows with desktop Microsoft PowerPoint. For PDFs, run `& .venv\Scripts\python.exe tools\pdf_to_md.py <source.pdf>` — one step: MarkItDown text + PyMuPDF 150-dpi page renders (`materials/md/<name>_media/pNN.png`), all listed in a "## Page images" gallery at the end of the file, with a generated provenance header. For PPTX (and legacy PPT), run `& .venv\Scripts\python.exe tools\pptx_to_md.py <source.pptx|source.ppt>` — MarkItDown text + 150-dpi page renders (PowerPoint COM → PDF → PyMuPDF). The export requests all slides, including hidden slides. MarkItDown also includes hidden-slide text but does not indicate which slides are hidden. When the exported PDF page count matches the slide count, `pNN.png` and "Page N" refer to slide N. If the counts differ, the converter labels images as "PDF page N" and reports the slide mapping and omitted slides as unknown; preserve that uncertainty and do not infer slide numbers or coverage. For other formats, use the venv's MarkItDown CLI and describe its actual output without assuming it generates page images or a provenance header. Record remaining conversion losses as caveats. Both converters accept an optional positional output path (`[output.md]`, not an `-o` flag); omit it to use the default path under `materials/md/`.
3. Analyze every generated page image with a vision-capable model via delegated subagents (≤5 `read_image` calls per subagent) — the main model never calls `read_image` itself. Discover registered routes via `list_subagent_models` and prefer `glm-5.3-flash` when an available route supports image input; otherwise choose another available image-capable route. If no suitable route is available or an image cannot be read, report the affected pages as not analyzed and do not guess. The subagent prompt must instruct it to stop and report the failure immediately if any `read_image` call fails. Expect a faithful per-page description — page topic, figures (axes, curves, blocks, legible values), tables, key equations, takeaways; report only what is visible and flag illegible parts. Insert each analysis after its matching image reference (`![Page N]` or `![PDF page N]`) as a plain `**Image analysis:**` block — no blockquote (consecutive quoted lines collapse into one paragraph); separate paragraphs, list items, and tables with blank lines so everything renders. Name the actual analysis model once in the provenance header when known, not per page.
4. Inspect the conversion quality: PDFs lose figures, equations flatten, tables mangle, PPTX speaker notes may or may not appear — verify against a skim of the original.
5. The script generates the provenance header; enrich it with document identification (course, author, source URL) and the image-analysis model when known.
6. Index the material in `progress.md` (topics covered, where the figures live), creating the file if needed. Before the learner agrees to setup, add the material to the Materials section and preserve existing entries, including quiz results; leave the learner profile, goals, curriculum, and unrelated sections unpopulated. Conversion details stay in the material's provenance header, never in `progress.md`.
7. Offer the learner a brief orientation summary. If an agreed curriculum exists, explain where the material fits; otherwise summarize its contents without assuming the learner's goals, and offer to set up a study plan afterward.
