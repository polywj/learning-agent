# Ingest

1. Find new source files in `materials/` (any depth; note the subfolder). Do not treat generated files under `materials/md/` as source materials.
2. Convert the source. These command examples use Windows PowerShell and `.venv\Scripts\python.exe`; on other platforms, use the virtual environment's Python executable and the platform's shell syntax. PDF conversion does not require PowerPoint. PPTX and legacy PPT conversion require Windows with desktop Microsoft PowerPoint.
   - **PDF:** Run `& .venv\Scripts\python.exe tools\pdf_to_md.py <source.pdf>`. This converts text with MarkItDown and renders each page with PyMuPDF at 150 dpi to `materials/md/<name>_media/pNN.png`. The Markdown includes a "## Page images" gallery and a generated provenance header.
   - **PowerPoint (PPTX/PPT):** Run `& .venv\Scripts\python.exe tools\pptx_to_md.py <source.pptx|source.ppt>`. This converts text with MarkItDown and exports slides through PowerPoint COM to PDF, then renders the PDF pages with PyMuPDF at 150 dpi. The export requests all slides, including hidden slides. MarkItDown also includes hidden-slide text but does not indicate which slides are hidden. When the exported PDF page count matches the slide count, `pNN.png` and "Page N" refer to slide N. If the counts differ, the converter labels images as "PDF page N" and reports the slide mapping and omitted slides as unknown; preserve that uncertainty and do not infer slide numbers or coverage. The Markdown includes a generated provenance header.
   - **Other formats:** Run the venv's MarkItDown CLI with `-o materials/md/<name>.md` to save the conversion under `materials/md/` (for example, `& .venv\Scripts\markitdown.exe <source-file> -o materials\md\<name>.md` in Windows PowerShell; use the equivalent CLI path and shell syntax elsewhere). Describe its actual output; do not assume it generates page images or a provenance header. Record known conversion losses as caveats.
   Both converter scripts accept an optional positional output path (`[output.md]`, not an `-o` flag); omit it to use the default path under `materials/md/`. Continue to step 3 only if page images were generated; otherwise skip steps 3–4.
3. Discover registered routes via `list_subagent_models` and prefer `glm-5.3-flash` when an available route supports image input; otherwise choose another available image-capable route. If no suitable route is available, report all page images as not analyzed, tell the learner that image analysis requires an image-capable route, and skip to step 5.
4. Analyze every generated page image with a vision-capable model via delegated subagents (≤5 `read_image` calls per subagent) — the main model never calls `read_image` itself. The subagent prompt must instruct it to stop and report immediately if any `read_image` call fails. Report affected pages as not analyzed; do not guess. Expect a faithful per-page description — page topic, figures (axes, curves, blocks, legible values), tables, key equations, takeaways; report only what is visible and flag illegible parts. Insert each analysis after its matching image reference as a plain `**Image analysis:**` block — no blockquote (consecutive quoted lines collapse into one paragraph); separate paragraphs, list items, and tables with blank lines so everything renders. Name the actual analysis model once in the provenance header when known, not per page.
5. Inspect conversion quality: PDFs may lose figures, flatten equations, or mangle tables; presentation conversions may omit or alter content. Verify against a skim of the original and record remaining losses as caveats.
6. For PDF and PowerPoint conversions, enrich the generated provenance header with document identification (course, author, source URL) and the image-analysis model when known.
7. Index the material in `progress.md` (topics covered, where the figures live), creating the file if needed. Before the learner agrees to setup, add the material to the Materials section and preserve existing entries, including quiz results. Do not populate learner profile, goals, curriculum, or session log until setup is agreed. Conversion details stay in the material's provenance header, never in `progress.md`.
8. Offer the learner a brief orientation summary. If an agreed curriculum exists, explain where the material fits; otherwise summarize its contents without assuming the learner's goals, and offer to set up a study plan afterward.
